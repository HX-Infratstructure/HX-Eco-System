Roles and boundaries

Repository

Holds current context, owner decisions, architecture, runbooks, smoke-test authorities, runner implementation, evidence indexes, and current state. The repository must contain enough context for an AI agent to operate without reconstructing decisions from chat history.

HX-5 CentCom

Owns permanent client tools, disposable run workspaces, synthetic fixtures, manifests, browser/UI automation, cleanup proof, and evidence assembly after its activation gate passes.

System under test

Owns only its installed application, approved configuration, real interfaces, and explicitly required smoke-namespaced temporary state. General test harnesses, venvs, fixtures, logs, and retained evidence do not belong on the SUT.

Standard lifecycle

READ CURRENT AUTHORITY
 → CREATE RUN
 → PROVE REACHABILITY
 → EXECUTE KNOWN-ANSWER TEST
 → CAPTURE RESULT
 → CLEAN UP
 → VERIFY CLEANUP
 → DETERMINE STATUS
 → REBOOT-PERSISTENCE PROOF
 → PROMOTE EVIDENCE
 → REVIEW / COMMIT
 → REMOVE DISPOSABLE RUN

The run directory is temporary. The durable artifacts are the accepted authorities and reviewed evidence.

PASS model

SUT service/base health
 AND known-answer component smoke test
 AND assigned MCP/UI companion gate where applicable
 AND cleanup succeeds
 AND cleanup verification succeeds
 AND reboot persistence
 AND reviewed retained evidence
 = BASE PASS / CLOSED
Functional success with failed or unverified cleanup is not a complete PASS.

Allowed states: PASS, FAIL, and NOT EXECUTABLE — PREREQUISITE OR OWNER DECISION REQUIRED.

Remote-first execution

  1. LAN/API/protocol endpoint.
  2. Native client from HX-5 such as psql or redis-cli.
  3. MCP client from HX-5.
  4. Direct-LAN browser/UI proof.
  5. Approved SSH remote command only when local execution is intrinsic to the component.

Do not copy a general-purpose test harness onto the SUT for convenience.

Limited integration

Limited integration is acceptable during base stand-up only when the dependency has already passed, it is required to prove the component's primary function, the data is synthetic/disposable, and all validation-only state is removed or explicitly approved to remain. A smoke-test dependency does not automatically become production architecture.

AI-centric repository contract

An AI agent must be able to determine from the repository alone: current state and priority, SUT role, exact acceptance criteria, CentCom execution process, runner commands, allowed temporary integration, cleanup requirements, status vocabulary, evidence destination, and stop conditions.

Do not rewrite acceptance criteria inside an in-progress run. If an authority is defective or stale, stop, correct it in a separate committed change, and begin a new run ID.

CentCom activation

HX-5 base/domain/GPU accepted
 AND Ollama + Ornith PASS
 AND HX-5 reboot persistence PASS
 AND CentCom toolset/bootstrap complete
 AND hx-smoke-doctor PASS
 AND remote known-good HX-2 probe PASS
 = CENTCOM SMOKE-RUNNER ACTIVE

DeepSeek Harness is not a prerequisite for this runner activation.

Deliberate non-goals

This system does not create a container platform, second deployment plane, permanent integration mesh, common reverse-proxy requirement, new firewall/TLS/DNS architecture, production test data, or automatic evidence commits.
