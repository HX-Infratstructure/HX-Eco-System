HX-5 CentCom — Smoke-Test Process and Procedures

Version: 1.0   Date: 2026-09-09   Status: current

Purpose. HX-5 CentCom is the standard remote smoke-test execution station after its own inference foundation has passed. Test code, fixtures, manifests, and logs stay on HX-5; the system under test keeps only its application, approved configuration, and explicitly smoke-namespaced temporary data.

Operating model

HX-5 CentCom
  |- disposable test workspace
  |- smoke-test runner/client tooling
  |- synthetic fixtures
  |- run manifest
  |- captured evidence
  |- cleanup verification
  |
  +---- LAN / API / CLI / approved SSH ----> System Under Test

HX-5 is the test runner, not a second deployment plane, configuration authority, reverse proxy, or permanent integration layer.

Core rules

  • Remote-first testing through the application's normal endpoint/interface.
  • No general test harness left on the SUT.
  • Local execution only when the product intrinsically requires it; temporary local files are removed and verified gone.
  • Synthetic/disposable data only.
  • Temporary objects use an obvious smoke namespace.
  • The current /smoke-tests/ procedure defines PASS.
  • Known-answer functional proof is required; process health alone is insufficient.
  • Cleanup and cleanup verification are part of PASS.
  • Reboot persistence is a separate minimum proof.
  • No permanent routes, firewalls, TLS, DNS, containers, NFS, or integration wiring are introduced by testing.

Remote execution patterns

PatternUse
Native network/APIPreferred for HTTP, REST, gRPC, Ollama, Qdrant, LightRAG, embeddings, routing, MCP HTTP, and similar services.
Native client on HX-5psql, redis-cli, FastMCP client, curl/Python standard-library clients, and other minimal client tooling.
Remote shellApproved SSH only when the primary contract cannot be proven remotely. Any copied temporary script is removed immediately and its removal verified.
Web UIDirect LAN UI on the application host. NGINX is not inserted unless HX-7 itself is the component under test.

Cleanup rule

Delete only objects created by the smoke test, then query the SUT again to prove they are gone. A successful functional result with unverified residue is FAIL / INCOMPLETE.

Status vocabulary

PASS
FAIL
NOT EXECUTABLE - PREREQUISITE OR OWNER DECISION REQUIRED

Example: the HX-4 reranker remains NOT EXECUTABLE until its exact checkpoint and serving runtime are pinned.

Recommended filename: YYYYMMDDTHHMMSSZ_<server>_<component>_<gate>_<description>.<ext>.

Failure and retry

Preserve failed evidence, classify the failure, correct only the identified issue, and create a new run ID. Never overwrite a failed run with the later PASS.

AND component smoke test from HX-5

AND cleanup + cleanup verification
AND reboot-persistence proof
AND retained evidence
AND server record / BUILD-STATE update
=
BASE PASS / CLOSED

The individual files under /smoke-tests/ remain authoritative for what each component must prove. This standard defines how HX-5 executes and records those proofs.
