Proof-chain model

HX uses cumulative proof with minimal live coupling. Each dependent run records prior_pass_evidence and limited_integration_plan. Use NONE when genuinely not applicable.

  • OmniRoute cites one approved model PASS and creates one temporary route.
  • LightRAG cites Qdrant + embedding + approved LLM PASS and uses only a synthetic disposable RAG path.
  • Mem0 cites Qdrant + embedding + approved LLM PASS and uses a disposable collection/memory.
  • Companion MCP/UI tests cite the parent core PASS.

Do not force a dependency merely to make tests appear connected.

Roles and boundaries

Repository

Owns ecosystem context, roadmaps, standards, smoke authorities, runner implementation, evidence indexes, and current state.

HX-5 CentCom

Owns client tools, disposable run workspaces, manifests, prior-proof references, synthetic fixtures, UI automation, cleanup verification, and evidence assembly after activation.

System under test

Owns only its installed application, approved configuration, real interfaces, and explicitly required smoke-namespaced temporary state.

PASS model

SUT service/base health
 AND required prior PASS evidence resolved
 AND known-answer component smoke test
 AND assigned MCP/UI companion gate where applicable
 AND cleanup succeeds + is verified
 AND reboot persistence
 AND reviewed retained evidence
 = BASE PASS / CLOSED
Functional success with failed or unverified cleanup is not a complete PASS.

Allowed states: PASS, FAIL, NOT EXECUTABLE — PREREQUISITE OR OWNER DECISION REQUIRED.

Remote-first execution

  1. LAN/API/protocol endpoint.
  2. Native client from HX-5 such as psql or redis-cli.
  3. MCP client from HX-5.
  4. Direct-LAN browser/UI proof.
  5. Approved SSH only when local execution is intrinsic.

Limited integration

Temporary integration is allowed only when the dependency already passed, the smoke roadmap/current accepted configuration requires it, the data is synthetic/disposable, and all validation-only state is removed. A smoke dependency does not automatically become production architecture.

Proof invalidation

Model/revision/dimension changes, vector/database behavior changes, major API/MCP changes, or SUT rebuild/config replacements can stale earlier evidence. Revalidate a stale prerequisite before using it for downstream PASS.
