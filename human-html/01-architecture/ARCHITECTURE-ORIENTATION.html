HX Eco-System — Architecture Orientation

Foundational orientation for the 17-server HX native-Linux AI ecosystem.

Cornerstone: the ecosystem architecture comes first. Validation proves the architecture; it does not define the architecture.

Model/data placement

  • HX-4 hosts BGE-M3 primary embeddings (1024), Nomic v1.5 alternate (768 default), and BGE-family reranking.
  • Never mix embedding-model vector spaces in one Qdrant collection; a model change requires a new collection and re-embedding.
  • Granite-Docling 258M stays with Docling on HX-16 and is CPU-first for base validation.
  • Only models on servers with accepted BASE PASS enter the active HX model/routing catalog.

Validation sits on top

After an agent understands the foundation, server ownership, target role, current state, dependency boundary, model/data placement, and BASE PASS expectation, it may use the validation authorities:

  • docs/00-control/HX-ECO-SYSTEM-SMOKE-TEST-ROADMAP.md — ordered proof dependencies.
  • docs/01-architecture/HX-SMOKE-TESTING-OPERATING-MODEL.md — validation architecture.
  • smoke-tests/ — exact component procedures.
  • HX-5 process/tooling — execution, cleanup, and evidence.

Current state boundary

HX-1, HX-2, HX-3 are current PASS/CLOSED as-built systems. HX-4 is next. HX-5 through HX-17 remain planned/not started except for staged repository documentation/runbooks. Design readiness is not as-built completion.
