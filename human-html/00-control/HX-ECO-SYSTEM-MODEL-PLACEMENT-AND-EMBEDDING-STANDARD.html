Placement decisions

CapabilityHostStandard
Granite-Docling 258MHX-16Embedded with Docling; CPU-first validation; GPU only if measured performance later justifies it.
BGE-M3HX-4Primary/default shared embedding model; 1024 dimensions.
Nomic Embed Text v1.5HX-4Alternate benchmark/fallback; 768 dimensions by default.

Architecture

HX-16 Docling
  ├─ Docling runtime
  ├─ Granite-Docling 258M
  └─ Docling MCP

HX-4 Meta-X
  ├─ GPT-OSS 20B
  ├─ BGE-M3
  ├─ Nomic Embed Text v1.5
  └─ BGE-family reranker

Granite-Docling is a document-understanding VLM and stays inside the Docling capability boundary. It is not the general HX vector embedding service and is not routinely routed through OmniRoute.

Why both embedding models

Both BGE-M3 and Nomic are installed so HX can benchmark retrieval quality, latency, GPU utilization, storage cost, and workload-specific performance without rebuilding the embedding host. BGE-M3 remains the default unless workload evidence justifies an exception.

Qdrant collection rule

Different embedding models occupy different semantic vector spaces and must never be mixed in one Qdrant collection.

Required collection metadata:
embedding_model
embedding_model_revision
embedding_dimension
embedding_normalization
embedding_service_version
chunking_profile
created_utc

Naming examples:
<domain>__bge_m3_1024
<domain>__nomic_v15_768

Model-switch procedure

  1. Create a new collection.
  2. Pin the new model/revision/dimension.
  3. Re-embed the source corpus.
  4. Load the new vectors.
  5. Run retrieval acceptance tests.
  6. Move the consumer only after PASS.
  7. Retain or retire the prior collection by owner decision.

There is no in-place embedding-model switch.

HX-5 decision

Shared embedding/reranking remains on HX-4 even if HX-5 receives two 16 GB GPUs. HX-5 headroom is reserved for CentCom, Ornith, DeepSeek Harness, development/test work, and future control-plane experimentation.

BASE PASS impact

HX-4: GPT-OSS 20B, embedding serving runtime, BGE-M3, Nomic v1.5, BGE reranker, API smoke tests, resource observation, reboot persistence.

HX-16: Docling, Granite-Docling 258M, conventional fallback pipeline, Docling MCP, representative document conversion, CPU performance observation, reboot persistence where applicable.
