Purpose

DeepSeek Harness must prove more than CLI/service health. The Harness is the HX meta-agent for AI-agent and AI-solution construction. Agents invoked beneath it are sub-agents that execute bounded application-building work under Harness orchestration.

The BASE PASS test remains intentionally small. It proves decomposition, delegation, artifact handoff, runnable application creation, independent validation, and Harness-level synthesis.

Preconditions

  • HX-5 base OS/domain/GPU state accepted.
  • HX-5 Ollama and assigned Ornith model have passed BASE PASS.
  • DeepSeek Harness native runtime/CLI or service is healthy.
  • At least one approved HX model endpoint is available.
  • A disposable local workspace is available.

The smoke test does not require a production database, NFS share, permanent MCP integration, permanent OmniRoute policy, or external cloud provider.

Required smoke test

Give the Harness a bounded request to build a minimal native Python AI CLI such as hx-agent-smoke. The application accepts a short text request, calls one approved HX Ollama model, returns a structured result containing at least intent, answer, and model, and includes a README and executable smoke test.

Harness responsibilities

  1. Interpret the solution requirement.
  2. Decompose it into discrete work packages.
  3. Delegate to at least two distinct sub-agent roles; three are preferred for the first test.
  4. Preserve context and artifact handoffs across sub-agents.
  5. Ensure the built application is actually executed.
  6. Route the result through an independent review step.
  7. Collect the outputs and return one final PASS/FAIL result.

BASE PASS criteria

#CapabilityProof required
1Meta-agent controlHarness owns the top-level task and orchestration flow.
2Task decompositionRequirement becomes multiple bounded work packages.
3Sub-agent delegationAt least two distinct sub-agent roles receive different work.
4Context/artifact handoffA downstream sub-agent uses an upstream artifact or decision.
5Application creationA real runnable application artifact is produced.
6AI executionThe generated application invokes an approved HX model and gets a usable result.
7Independent validationReviewer/validator checks the implementation against acceptance criteria.
8Harness synthesisHarness reconciles the sub-agent outcomes and produces one final result.
9EvidenceDelegation, artifacts, backend/model, test output, and final status are captured.
10Reboot persistenceAfter reboot, Harness can again execute a short delegated sub-agent task.

Closure rule

Harness runtime/service health = PASS
                 AND
Harness meta-agent solution-building smoke test = PASS

Process health alone is not sufficient to close DeepSeek Harness BASE PASS.

Non-goals

The smoke test does not require the full HX Agent Factory, permanent registry population, production deployment, full fleet orchestration, permanent MCP wiring, permanent OmniRoute routing, RAG/memory integration, NFS configuration, or production secrets/data.

Evidence

Retain HX-5 host/time, Harness version, model/backend, top-level request, sub-agent roles and work packages, artifact paths, execution output, validation result, Harness synthesis, and final PASS/FAIL. Update the HX-5 server record and BUILD-STATE when the gate closes.
