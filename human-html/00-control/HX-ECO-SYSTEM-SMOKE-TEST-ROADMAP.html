Core rule: cumulative proof, minimal live coupling. A later smoke test consumes prior PASS evidence only when that earlier capability is a real prerequisite. HX does not create unnecessary cross-service wiring merely to make the tests look sequential.

Proof-chain rule

Every CentCom-run test records prior_pass_evidence and limited_integration_plan. Use NONE where appropriate. Dependent tests cite exact current retained evidence paths or accepted server records.

LightRAG example
prior_pass_evidence:
  Qdrant PASS + BGE-M3 PASS + approved LLM PASS
limited_integration_plan:
  synthetic LightRAG document through those accepted services;
  remove validation state afterward

Roadmap

Phase 0 — Cornerstone proof

HX-1 identity/DNS/Kerberos/NTP, HX-2 Qwen-X, and HX-3 Coder-X are already PASS/CLOSED. These establish the foundation and known-good inference reference.

Phase A — Inference + CentCom activation

HX-4 GPT-OSS → HX-4 embeddings → HX-4 reranker → HX-5 Ornith → CentCom remote-runner activation against known-good HX-2.

Exit: accepted generative/retrieval inference plus a proven HX-5 remote test station.

Phase B — State / retrieval substrate

PostgreSQL core + MCP → Redis core + MCP → Qdrant core + Web UI + MCP.

Qdrant deliberately uses deterministic raw vectors so its core proof does not depend on embeddings.

Phase C — Routing / MCP development / control

OmniRoute → FastMCP → DeepSeek Harness → NGINX dev/test.

Temporary integrations: OmniRoute uses one proven model; NGINX uses one temporary HX-5 private-IP upstream; DeepSeek Harness uses one approved model directly.

Phase D — Knowledge acquisition

Docling + Granite-Docling + MCP → Crawl4AI + MCP. Both use deterministic local/synthetic inputs and do not require production RAG wiring.

Phase E — RAG / memory

LightRAG + MCP → Mem0 + MCP.

This phase intentionally consumes earlier proof: Qdrant + accepted embedding + approved LLM. PostgreSQL/Redis are added only if the accepted component configuration genuinely uses them.

Phase F — Agents / workflow

Deep Agents → n8n + Web UI + MCP.

Deep Agents proves its LOB-agent factory with a tool-calling model, local synthetic rules, and disposable thread state; it does not require production RAG/memory for BASE PASS.

Phase G — User interaction

Open WebUI proves one direct known-answer conversation against a current approved Ollama model, then removes validation-only connection state.

MCP companion tests do not depend on the HX-15 FastMCP server. UI companion tests use direct LAN access and do not require HX-7 NGINX unless NGINX itself is under test.

Failure / invalidation

  • A failed or missing required prerequisite blocks downstream PASS.
  • Material dependency changes can stale earlier evidence and require revalidation.
  • Cleanup failure prevents complete PASS.
  • Temporary validation wiring never becomes permanent architecture by implication.

Current position

  • Phase 0: PASS/CLOSED foundation exists for HX-1, HX-2, HX-3.
  • Phase A: next; HX-4 is the next deployment target.
  • CentCom tooling is designed but not active until HX-5 is built and activation evidence passes.
  • Later phases remain gated by deployment readiness plus prior proof dependencies.
