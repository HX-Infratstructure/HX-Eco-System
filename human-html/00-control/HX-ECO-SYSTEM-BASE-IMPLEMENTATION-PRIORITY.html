HX Eco-System — Base Implementation Priority and Server Map

Version: 1.7   Status: evergreen current

Evergreen roadmap. The authoritative agent source is docs/00-control/HX-ECO-SYSTEM-BASE-IMPLEMENTATION-PRIORITY.md. The roadmap defines what must pass; standalone files under /smoke-tests/ define how component proof is executed.

Governing rule

one server
→ verify base state
→ install assigned workload
→ prove primary function
→ reboot
→ record evidence
→ close PASS
→ move to next server

Native Linux + systemd remains the deployment standard. Temporary smoke-test integration must be minimal, synthetic/disposable, validation-only, and removed after evidence capture unless explicitly approved as permanent.

Planned infrastructure follow-ons — lower priority

Fleet SSH pass / non-interactive SSH configuration

Standardize the approved non-interactive fleet authentication pattern while preserving working interactive SSH. No immediate action required.

NFS mounts and shared filesystem configuration

Define authoritative exports, consumers, stable mount points, permissions, and reboot persistence after server/storage roles are confirmed. Historical prototype mounts are not automatically recreated. No immediate action required.

Integration readiness

Base build closes only after every assigned service, companion UI/MCP endpoint, required component smoke test, cleanup step, reboot-persistence gate, server record, and build-state update is complete. Permanent service-to-service integration remains a separate program.
